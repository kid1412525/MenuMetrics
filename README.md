# システムモニタ (MenuMetrics)

macOS のメニューバーに常駐して、**CPU / メモリ / GPU の使用率と温度**を表示する
アプリです。クリックすると内訳とプロセス一覧のパネルが開きます。

Dock にも Cmd+Tab にも出ません (`LSUIElement`)。

## ビルドと導入

Xcode は不要で、**コマンドラインツール**だけで完結します。

```sh
./build.sh --install     # ビルドして /Applications に入れて起動
./build.sh --run         # ビルドして build/ から起動
./build.sh               # ビルドのみ
./build.sh --native      # 実行中のマシンのアーキテクチャだけ (速い)
```

`--native` を付けない場合は arm64 + x86_64 のユニバーサルバイナリを作ります。

常駐させるには、パネル下部の **設定 → ログイン時に起動** をオンにしてください。

## 表示している内容

### メニューバー

`CPU 23% / MEM 61% / GPU 11% / TEMP 48°` のように 2 行で並びます。
右クリック (または設定) で**グラフ表示**に切り替えると、直近 60 サンプルの
スパークラインの上に数値が重なる表示になります。
表示する項目と更新間隔 (1〜5 秒) は設定から変えられます。

### パネル (クリックで表示)

| 区分 | 内容 |
|---|---|
| CPU | 全体 / ユーザー / システム、高性能・高効率コア別、コアごとのバー、ロードアベレージ |
| メモリ | アプリ・確保済み・圧縮・キャッシュの積み上げ、スワップ、メモリ圧力 |
| GPU | 使用率、レンダラー / タイラー使用率、GPU が確保しているメモリ |
| 温度 | SoC ダイの平均・最高、GPU 付近、SSD、バッテリー、全センサー一覧 |
| プロセス | CPU 順 / メモリ順の上位 5 件 |

パネルの高さは中身の実測値に合わせて伸縮します (画面に収まる範囲で頭打ち)。
高さを固定にすると行が途中で切れて見えるためで、`GeometryReader` で測った
高さを `NSPopover.contentSize` に反映しています。SwiftUI 側で
`.frame(maxHeight:)` を使うとポップオーバーが最小サイズに潰れるため、
サイズの決定は AppKit 側で行っています。

## 実装のしかた

| メトリクス | 取得方法 |
|---|---|
| CPU | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` の tick 差分 |
| メモリ | `host_statistics64(HOST_VM_INFO64)` + `sysctl vm.swapusage` |
| GPU | IORegistry の `IOAccelerator` → `PerformanceStatistics` |
| 温度 | IOKit の非公開 API `IOHIDEventSystemClient` (root 不要) |
| プロセス | `proc_listpids` + `proc_pid_rusage` |

プロセスの CPU 使用率はアクティビティモニタと同じ基準 (100 % = 1 コア) です。
`proc_pid_rusage` が返す CPU 時間は **ナノ秒ではなく mach absolute time 単位**
なので、`mach_timebase_info` で換算しています (Apple Silicon では 1 tick =
125/3 ns で、換算を忘れると実際の 1/41.7 の値になります)。

メモリの区分はアクティビティモニタの「メモリ」タブに合わせてあります
(使用済み = アプリメモリ + 確保済みメモリ + 圧縮)。

### 温度センサーについて

温度は公開 API では取得できないため、IOKit の非公開シンボルを `dlsym` で
引いて使っています (権限昇格は不要)。シンボルが見つからない環境では温度の
表示だけが自動的に消えます。

センサー名と部位の対応は Apple が公開していないので、**M2 Pro の実機で
CPU 負荷と GPU 負荷を別々にかけ、反応を計測して分類**しました:

| センサー名 | 判定 | 根拠 (負荷時の上昇幅) |
|---|---|---|
| `PMU tdie*`, `PMU TP*` | SoC ダイ (CPU/GPU) | CPU 負荷 +1.17 ℃ / GPU 負荷 +1.56 ℃ |
| `PMU tdev7` | GPU 寄り | CPU 負荷 +0.92 ℃ に対し GPU 負荷 +2.35 ℃ |
| `PMU tcal` | 校正値のため除外 | 常に 51.85 ℃ で変化しない |
| `NAND CH*` | 内蔵 SSD | — |
| `gas gauge battery` | バッテリー | — |

Apple Silicon は CPU と GPU が同じダイに載っているため両者の温度は
ほぼ連動します。GPU 温度は「推定」と明示して表示しています。

センサーは 1 個読むのに約 1 ms かかり、64 個すべてを読むと 1 回 62 ms に
なります。常時表示ではダイの代表センサー 6 個 + GPU/SSD/バッテリーの
計 9 個だけを読み、詳細パネルを開いている間だけ全件読みます。
ダイのセンサーは互いに 1 度以内に収まるため、この間引きによる平均値の
差は実測で 0.05 ℃ でした (全件 41.97 ℃ / 代表のみ 41.92 ℃)。

## 自分自身の負荷

監視ツール自体が重くては本末転倒なので、各モニターの実測値です
(M2 Pro, 1 回あたり):

| モニター | コスト | 備考 |
|---|---|---|
| CPU | 0.006 ms | |
| メモリ | 0.003 ms | |
| GPU | 0.033 ms | IOAccelerator のサービスを使い回す |
| 温度 (代表 9 個) | 9.6 ms | 最短 3.5 秒間隔でキャッシュ |
| 温度 (全 64 個) | 65.9 ms | 詳細パネルを開いている間のみ |
| プロセス一覧 | 0.6 ms | 詳細パネルを開いている間のみ |

状態別の実測値 (既定の 2 秒間隔):

| 状態 | CPU | 備考 |
|---|---|---|
| メニューバー表示中・パネル閉 | 1 コアの **0.10 %** | 通常の常駐状態 |
| メニューバーが隠れている | **0 %** | サンプリングごと停止 |

常駐メモリは約 35 MB です。

### 「エネルギーを著しく消費中」への対処

初期の実装は macOS のバッテリーメニューで「エネルギーを著しく消費中」と
表示されていました。実測すると **1 コアの 30.4 %、アイドルウェイクアップ
778 回、エネルギー影響度 27.9** という値でした。

`sample` でスタックを取ると、実行時間の大半が `libswiftObservation` の
`ObservationTracking.cancel()` や `AnyKeyPath.hash(into:)` に集中していました。
原因は、**閉じている詳細パネル (SwiftUI) が 2 秒ごとに再評価されていた**ことです。
`NSPopover` の中身を起動時に作って保持していたため、画面に出ていないビューが
`@Published` の更新のたびに観測を張り直していました。

対処:

| 対処 | 内容 |
|---|---|
| SwiftUI を常時経路から外す | メニューバーの更新は `ObservableObject` ではなく素のコールバックで配る。`@Published` はパネルを開いている間だけ更新する |
| パネルの中身を遅延生成 | 一度も開かなければ SwiftUI のビュー階層を作らない |
| 見えていないときは止める | ステータス項目のウィンドウの `occlusionState` で、メニューバーが隠れている (フルスクリーン等) / 画面が消えている間はサンプリング自体を停止。`NSApp.occlusionState` だとデスクトップ表示中にも止まってしまうため、項目そのもので判定する。復帰時は約 0.3 秒で最初の値を出す |
| 起床をまとめる | タイマーの leeway を間隔の 30 % に広げ、カーネルに他のタイマーと合流させる |
| 電源に追従 | 低電力モード中は最短 5 秒、電池駆動中は最短 3 秒に間隔を伸ばす |
| 無駄な再描画を止める | 数値表示では、描かれる文字が前回と同じなら描き直さない |

結果は **30.4 % → 0.10 %、アイドルウェイクアップ 778 → 0、
エネルギー影響度 27.9 → 0.0** です。

タイマーの生成と破棄は必ず採取キュー上で行います。メインスレッドから
直接触ると、キュー側の代入と競合して止めたはずのタイマーが動き続けます
(実際に検証で再現しました)。

## 制約

- **root 所有のプロセスは一覧に出ません。** `proc_pid_rusage` は他ユーザーの
  プロセスを読めないためです (実測で 684 件中 459 件が読めました)。
  アクティビティモニタは特権ヘルパーでこれを回避していますが、
  このアプリは権限昇格をしません。
- **配布用の署名がありません。** ad-hoc 署名でビルドするので、このマシンでは
  そのまま動きますが、他の Mac にコピーすると Gatekeeper に止められます。
  そのため「ログイン時に起動」の登録が失敗する場合があります
  (失敗時は設定パネルに理由が出ます)。
- GPU 使用率は内蔵 GPU の値です。外付け GPU が複数ある場合は使用率が
  最も高いものを表示します。
- 4 項目すべてを表示すると幅が約 140 pt になります。メニューバーが
  混んでいて表示されない場合は、設定で項目を減らすか、グラフ表示ではなく
  数値表示にしてください。

## ファイル構成

```
Sources/MenuMetrics/
├── main.swift              エントリポイント
├── AppDelegate.swift       ステータスアイテムとポップオーバーの制御
├── Metrics/
│   ├── Snapshot.swift      1 回分の計測結果の型
│   ├── CPUMonitor.swift    CPU 使用率とコア構成
│   ├── MemoryMonitor.swift メモリとスワップ
│   ├── GPUMonitor.swift    GPU 使用率
│   ├── ThermalMonitor.swift 温度センサー
│   ├── ProcessMonitor.swift プロセス一覧
│   ├── MetricsEngine.swift 定期実行と配信
│   └── Settings.swift      設定の永続化
└── UI/
    ├── StatusItemView.swift メニューバーの描画
    ├── DetailView.swift     詳細パネル
    ├── Components.swift     バーやグラフの部品
    ├── MetricStyle.swift    色と書式
    └── LoginItem.swift      ログイン項目の登録
```
